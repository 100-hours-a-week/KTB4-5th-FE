# 공유 냉장고 추방 후 화면 복구

## 계약과 설계

- `event: kicked`, `data: {}`를 사용한다. 이벤트 데이터로 냉장고를 선택하지 않는다.
- 기존 보호 영역의 SSE 연결 하나를 재사용한다. 냉장고 변경 시 기존 연결을 닫는다.
- `kicked`를 받으면 연결과 재연결 타이머를 종료하고 공통 복구 기능을 실행한다.
- 복구 기능은 캐시된 current와 선택 ID를 비운다. 기존 `useCurrentRefrigeratorRecovery`가
  `GET /api/v1/refrigerators/current`를 새로 호출해 응답의 냉장고를 선택한다.
- 이전 냉장고의 재고·구성원·초대·마이페이지·알림 Query를 제거하고 진행 중인 조회도
  취소한다. 사용자 소유 이미지 분석 캐시는 유지한다.
- 홈으로 replace 이동하고, current 조회 중에는 공용 로딩 화면으로 기존 화면을 가린다.
  조회 실패 시 기존 화면을 복원하지 않고 오류와 재시도 버튼을 표시한다.
- 결과로 ID가 설정되면 새 SSE 연결을 열고, `connected`에서 기존 계약대로 알림 목록의
  cursor를 초기화해 목록·미읽음 수와 이미지 분석을 갱신한다.
- Query·Mutation 캐시에서 `REFRIGERATOR-403-001`을 확인해도 같은 복구를 실행한다.
  조회는 현재 냉장고의 키만 처리하고, 변경은 해당 연결이 유지되는 동안 시작한 요청만
  처리한다. 이전 연결 이벤트와 이전 냉장고에서 시작한 변경의 늦은 실패는 무시한다.
- EventSource 오류에서 HTTP 코드나 Problem Details를 직접 읽지 않는다.

## 단계별 진행

1. Feature에 공통 복구 기능을 두고 현재 냉장고 Gate에서 로딩·오류·재시도를 처리한다.
2. 기존 SSE에 `kicked` 리스너를 추가하고 Query·Mutation 오류 복구를 연결한다.
3. 전환 중 늦게 이어진 알림 갱신이 제거한 목록을 다시 만들지 못하도록 차단한다.
4. 신호 수신·유실 시 403 복구·중복 및 지연 이벤트·요청 취소·조회 실패와 재시도를 검증한다.
5. 백엔드 배포 후 두 브라우저에서 실제 내보내기를 실행해 대상자 전환과 나머지 구성원의
   기존 알림 동작을 확인한다.

## 백엔드 및 배포 확인

이 저장소는 프론트엔드만 포함한다. 백엔드는 추방 및 개인 냉장고 활성화의 DB 커밋 후
추방 사용자와 기존 공유 냉장고가 모두 일치하는 모든 연결에 `kicked`를 보내야 한다.
롤백 시 발행하지 않으며 인앱 알림과 푸시 성공 여부에 의존하지 않는다.

SSE 프록시는 이벤트를 변형 없이 전달한다. 배포 환경에서도 버퍼링을 끄고 쿠키 인증과
25초 heartbeat를 확인해야 한다. 서버 계약 구현·배포와 실제 브라우저 간 전달은 별도 검증한다.

이벤트 재전달은 보장하지 않는다. 신호를 놓치고 REST 접근 오류도 발생하지 않으면 화면이
즉시 바뀌는 것을 보장할 수 없다. 별도 polling이나 이벤트 ID·ACK는 추가하지 않는다.
