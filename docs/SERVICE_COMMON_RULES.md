# 다먹자 서비스 공용 규칙

## 1. 문서 목적과 적용 범위

이 문서는 다먹자 서비스의 화면 설계와 프론트엔드·백엔드 구현에서 공통으로
적용할 제품 정책을 정의한다. 화면별 명세에 별도 예외가 명시되지 않은 경우 이
문서를 기본값으로 사용한다.

- 날짜 판정과 표시는 `Asia/Seoul`을 기준으로 한다.
- 서버는 시각 데이터를 UTC로 저장하고, 판정·표시 전에 KST로 변환한다.
- 공용 UI의 컴포넌트 책임과 코드 배치는
  [공통 컴포넌트 설계 규칙](./COMMON_COMPONENT_RULES.md)을 따른다.
- 애플리케이션 코드의 레이어와 import 방향은
  [FSD 아키텍처 규칙](./FSD_ARCHITECTURE.md)을 따른다.
- 이 문서의 무채색 hex 값은 와이어프레임 기준이다. 디자인 단계에서 컬러
  팔레트가 확정되면 값만 교체하고 상태 구분 원칙은 유지한다.

## 2. 유효기간

### 2.1 만료·임박·여유 판정

모든 상태는 KST 날짜의 시작인 `00:00:00`을 경계로 판정한다.

| 상태 | 판정 | D-day | 표시 강도 | 카드 좌측 상태 바 |
| --- | --- | --- | --- | --- |
| 만료 | 유효기간이 오늘보다 이전 | `D+1` 이상 | 가장 강함 | 표시 |
| 임박 | 유효기간이 오늘부터 3일 후까지 | `D-0`~`D-3` | 중간 | 표시 |
| 여유 | 유효기간이 오늘보다 4일 이상 이후 | `D-4` 이상 | 가장 약함 | 미표시 |

유효기간 당일은 하루 종일 유효하며 `D-0`, 즉 임박 상태로 표시한다. 유효기간
다음 날 `00:00:00`부터 만료 상태가 된다.

예를 들어 오늘이 2026.08.26이라면 다음과 같이 판정한다.

| 유효기간 | 상태 |
| --- | --- |
| 2026.08.25 | 만료 (`D+1`) |
| 2026.08.26 | 임박 (`D-0`, 오늘까지) |
| 2026.08.27 | 임박 (`D-1`) |
| 2026.08.29 | 임박 (`D-3`) |
| 2026.08.30 이후 | 여유 (`D-4` 이상) |

상태는 매일 자정에 오늘 날짜와 유효기간을 기준으로 갱신한다. 앱이 백그라운드에
있는 동안 자정을 넘긴 뒤 다시 활성화되면 목록·상세·홈 요약을 재계산해 다시
렌더링한다. 알림 발송은 화면 상태 갱신과 별개이며, 매일 오전 8시에 전체 사용자
대상 집계를 한 번 수행한다.

### 2.2 상태 표시

상태는 뱃지, 카드 좌측 상태 바, 채움 여부의 세 가지 수단으로 구분한다. 색
하나에만 의존하지 않으며 시각 강도는 `만료 > 임박 > 여유` 순으로 적용한다.

| 상태 | 뱃지 | 좌측 상태 바 |
| --- | --- | --- |
| 만료 | `#18181B` 채움, 흰 글자 | `#18181B` |
| 임박 | `#E4E4E7` 채움, `#18181B` 글자 | `#71717A` |
| 여유 | 흰 배경, `#D4D4D8` 1.5px 테두리, `#52525B` 글자 | 없음 |

뱃지 규격은 `51 × 30`, radius `9999`, 패딩 `6 / 14`, `12px Bold`이다.

### 2.3 날짜만 입력하는 이유

- 유효기간은 날짜만 입력받는다. 시·분 입력 필드는 제공하지 않고 캘린더에서
  날짜만 선택한다.
- 내부적으로 선택한 날짜의 `23:59:59`까지 유효한 것으로 본다.
- 실제 식품의 만료 시각은 제조사 표기에 따라 달라 이를 정확히 처리하려면 매번
  시·분을 입력받아야 한다. 이는 입력 부담과 오입력 위험을 높인다.
- 서비스 목적은 오늘 안에 먹을 재료를 골라 요리를 추천하는 것이므로 하루 단위
  판정으로 충분하다.
- 국내 식품 표시 기준상 유통기한은 판매 가능 기한이며 소비기한은 이보다 길게
  설정된다. 따라서 유통기한 당일까지 추천 대상인 임박 상태로 취급한다.
- 이 기준은 정상적인 보관 상태를 전제로 한다. 화면에서는 “오늘까지 드세요”
  수준으로 안내하며 안전을 단정하지 않는다.

## 3. 리스트 조회와 무한 스크롤

모든 리스트 조회는 숫자 페이지 UI가 아닌 스크롤 기반 페이징을 사용한다.

- 최초 조회와 다음 조회의 크기는 각각 10건이다.
- 요청 중인 페이지를 중복 요청하지 않는다.
- 검색어·필터·정렬이 바뀌면 기존 목록을 비우고 첫 페이지부터 다시 조회한다.
- 마지막 페이지에 도달하면 추가 요청을 중단한다.
- 목록 항목을 눌러 다른 페이지로 이동했다가 돌아오면 스크롤 위치, 필터, 정렬
  상태를 복원한다.
- 다음 페이지를 조회하는 동안에는 축소형 로딩 UI를 목록 하단에만 표시한다.
- 요리 추천 목록은 최대 10건으로 고정하며 무한 스크롤을 사용하지 않는다.

새로고침 시 입력 중인 값은 초기화한다. 필터·정렬 조건의 전체 유지 범위는 별도
확정 전까지 보류하되, 위에서 명시한 **목록에서 상세로 이동 후 복귀하는 경우**는
반드시 유지한다.

## 4. 로딩·에러·빈값 공용 UI

로딩(1a), 에러(1b), 빈값(1c)은 화면마다 새로 만들지 않고 공용 컴포넌트의
인스턴스를 사용한다. 세 상태의 골격은 `56px 원형 아이콘 → 제목 → 보조 문구 →
액션 슬롯` 순서로 동일하다. 액션이 없어도 슬롯 높이를 유지하여 상태 전환 시
레이아웃이 움직이지 않게 한다.

| 상태 | 아이콘·문구 | 액션 |
| --- | --- | --- |
| 1a 로딩 | 스피너, “OO를 불러오는 중입니다” | 비움 |
| 1b 에러 | 경고 아이콘, 에러 코드에 정의된 문구 | 다시 시도 |
| 1c 빈값 | 상황에 맞는 아이콘, 다음 행동 안내 | 해당 행동으로 이동하는 버튼 |

- 세 상태를 동시에 표시하지 않는다. 판정 우선순위는 `로딩 > 에러 > 빈값`이다.
- 에러 재시도는 직전 정렬·필터·페이지 조건을 유지한다.
- 네트워크 오류와 서버 오류의 문구를 구분한다.
- 재시도 중에도 직전에 받은 데이터는 지우지 않는다.
- 화면별 빈 상태 문구는 각 화면 명세에서 정의한다.
- 버튼으로 시작한 동작은 공용 상태 UI 대신 해당 버튼만 로딩 상태로 바꾼다.
- 적용 대상은 재고 목록·상세·등록(OCR), 알림, 요리 추천·상세이다.

### 4.1 재시도

- 다시 시도 버튼은 요청 중 “로딩 중”으로 바꾸고 중복 탭을 막는다.
- 연속 3회 실패하면 “잠시 후 다시 시도해 주세요”로 안내 문구를 바꾼다.
- 연속 5회 실패하면 60초 동안 재시도를 막고 남은 시간을 표시한다.
- 화면을 벗어나면 재시도 횟수를 초기화한다.

## 5. 입력 검증과 텍스트 입력

### 5.1 공통 검증 방식

- 위반 사유는 입력칸 바로 아래 한 줄 헬퍼 텍스트로 표시한다. 토스트·모달·경고
  팝업으로 대체하지 않는다.
- 평상시에는 `#71717A`로 입력 규칙을 안내하고, 위반 시 같은 위치에
  `#DC2626`으로 사유만 표시한다.
- 헬퍼 영역은 항상 공간을 차지하여 오류 발생 시 아래 요소가 밀리지 않게 한다.
- 글자 수·형식·범위는 입력 중 즉시 검사한다. 중복 확인처럼 서버가 필요한
  검사는 다음 또는 저장을 눌렀을 때 수행한다.
- 오류가 겹치면 `비어 있음 > 형식 > 범위 > 금칙어 > 중복` 순서에서 가장 앞선
  오류 하나만 표시한다.
- 오류가 하나라도 있거나 필수 값이 비어 있으면 해당 화면의 주 버튼(다음·저장·
  등록)을 비활성화한다.
- 금칙어는 `slang.csv`를 기준으로 검사한다.
- 문구는 아래 표준 문구에서만 선택하고 화면별로 새로 작성하지 않는다.

| 상황 | 표준 문구 |
| --- | --- |
| 비어 있음 | “OO을 입력해주세요” |
| 일반 글자 수 | “2~10자로 입력해주세요” |
| 닉네임 글자 수 | “최소 2글자, 최대 10글자 사이로 입력해주세요.” |
| 수량 범위 초과 | “100개까지 입력할 수 있어요” |
| 숫자 범위 초과 | “20,000 이하로 입력해주세요” |
| 금칙어 | “사용할 수 없는 단어가 포함돼 있어요” |
| 중복 | “이미 사용 중이에요” |
| 날짜 미선택 | “유통기한을 선택해주세요” |
| 품목 한도 | “n종을 줄여야 등록할 수 있어요” |
| 건수 상한 | “한 번에 20건까지 등록할 수 있어요” |
| 로그인 실패 | “아이디 또는 비밀번호를 확인해 주세요” |
| 지난 날짜 | “지난 날짜는 선택할 수 없어요” |
| 네트워크 | “인터넷 연결을 확인해 주세요” |

### 5.2 텍스트 길이

- 텍스트 필드는 최소 2글자, 최대 10글자이다.
- 헬퍼 문구는 “최소 2글자, 최대 10글자 사이로 입력해주세요.”를 사용한다.
- 앞뒤 공백은 저장 전에 제거하며 글자 수에도 포함하지 않는다.

## 6. 재고 정책

### 6.1 재료 단위

- 무게는 선택 입력이다.
- 고체류는 `g`, 액체류는 `ml`를 사용하며 무게 단위는 이 둘 중에서만 고른다.
- 리터 입력은 밀리리터로 환산한다. 예: `1.5L → 1500ml`.
- 수량 단위는 `개`로 고정하며 사용자가 선택하지 않는다.

### 6.2 품목 종류와 수량 한도

냉장고는 1대로 고정하며 냉장·냉동을 합쳐 최대 100종을 보관한다. 품목 종류는
수량 합계가 아니라 `이름 + 보관 방법 + 유효기간` 조합으로 계산한다.

- 세 값이 모두 같으면 같은 품목이다. 재등록 시 새 품목을 만들지 않고 기존
  수량에 합산하며 100종 한도에 영향을 주지 않는다.
- 이름이 같아도 보관 방법 또는 유효기간이 다르면 별개 품목이다.
- 한 품목의 수량은 1~100 사이 정수이며 상한은 100개이다.
- 현재 품목 종류 수가 100 미만일 때만 신규 품목을 등록할 수 있다.
- 100종에 도달하면 신규 품목 등록만 막고, 기존 품목의 수량 증가·수정은
  100개까지 허용한다.
- 100종 상태에서 탭바 등록 버튼이나 빈 상태 중앙 등록 버튼을 누르면 “정리 후
  등록해 주세요” 토스트를 표시한다.
- 홈 용량 카드와 목록 요약은 `n / 100종` 형식으로 표시한다.

### 6.3 삭제와 만료 처리

- 삭제 대상은 별도 위치에 백업하지 않으며 관련 키도 함께 삭제한다.
- 개인정보가 포함된 데이터는 삭제 전에 반드시 사용자 확인을 받는다.
- 만료 처리로 재고 수량이 0이 되면 해당 재고 품목을 삭제하고 품목 수를 1
  줄인다.
- 재고 품목을 삭제해도 해당 재료의 요리 적용 이력과 만료·임박 알림 기록은
  유지한다.

## 7. 버튼·모달·바텀시트·토스트

### 7.1 버튼

| 상태 | 스타일 |
| --- | --- |
| Primary | `#18181B` 채움, 흰 글자, radius `9999`, 높이 `48` |
| Secondary | 흰 배경, `#E4E4E7` 2px 테두리, 검정 글자 |
| Disabled | `#F4F4F5` 배경, `#A1A1AA` 글자, 탭 무반응 |

### 7.2 모달

- radius는 `24`, 딤은 `#18181B` 35%이다.
- 바깥 영역을 눌러 닫을 수 없으며 열린 동안 뒤 요소와 상호작용할 수 없다.
- 확인형 문구는 “OO를 OO할까요?” 제목, 필요한 보조 문구, `[취소] [실행]`
  버튼 순서로 구성한다. 실행 버튼만 검정으로 채운다.
- 확인형은 등록, 수정, 삭제(만료), 뒤로가기, 취소, 로그아웃 6종이다.
- 결과 요약이 필요한 경우에만 `[확인]` 버튼 하나의 완료형 모달을 사용한다.
- 저장·수정·삭제의 단순 성공 안내는 모달 대신 토스트를 사용한다.
- 되돌릴 수 없는 동작은 보조 문구에 그 사실을 반드시 밝힌다.
- 입력값이 하나도 없을 때 뒤로가면 확인 모달 없이 바로 이동한다.

| 참여자 내보내기 | v2 전용 `SHARE-001`. 방장에게만 노출하고 확인 후 대상자에게 알림 발송 |
| 초대 코드 재발급 | v2 전용 `SHARE-002`. 기존 코드가 즉시 무효화되므로 1회 확인 |
| 카메라 권한 안내 | `REG-001`, `REG-002-2`에서 권한 거부 시 표시하고 대안 행동 `[직접 입력]` 제공 |
| 한도 도달 안내 | 진입점 비활성만으로 100종 한도 이유가 전달되지 않을 때 표시 |
| 잠금 안내 | v1 전용으로 정의된 안내형 모달 |

안내형은 사용자가 선택할 것이 없고 상황만 알리면 되는 경우이며 `[확인]` 버튼
하나만 둔다. 탈퇴·일괄 만료·내보내기·재발급의 보조 문구에는 되돌릴 수 없음을
반드시 명시한다. `(v1 전용)` 또는 `(v2 전용)` 표시가 없는 모달은 두 버전에서
공통으로 사용하며, 공용 영역을 변경할 때 `new_v1`과 `new_v2`에 같은 내용을
반영한다.

### 7.3 바텀시트

- 상단 radius `24`와 드래그 핸들을 사용한다.
- 값을 고르는 바텀시트는 바깥 탭 또는 아래로 스와이프하여 닫을 수 있다.
- 이 닫기 동작은 취소와 동일하게 처리한다.

### 7.4 토스트

- 화면 하단에서 나타나 3초 후 자동으로 사라지며 동시에 하나만 표시한다.
- 성공은 검정 배경과 흰 글자, 실패는 흰 배경과 테두리를 사용한다.
- 한 줄을 원칙으로 하고 최대 두 줄까지만 허용하며 에러 코드는 노출하지 않는다.
- 같은 토스트가 연속 발생하면 새로 추가하지 않고 기존 토스트의 남은 시간을
  3초로 초기화한다.
- 화면 이동과 함께 발생하면 이동을 마친 화면에서 표시한다.

## 8. 탭바

- 홈·냉장고·등록·추천·MY의 5개 항목을 모든 주요 화면 하단에 고정한다.
- 현재 탭의 아이콘과 라벨은 `#18181B`, 나머지는 `#A1A1AA`로 표시한다.
- 가운데 등록은 화면 이동 탭이 아니라 재료 등록 `REG-001` 진입 버튼이다.
- 품목이 100종에 도달하면 등록만 비활성화하고 나머지 탭은 유지한다.
- 현재 탭을 다시 누르면 해당 화면의 스크롤을 최상단으로 이동한다.
- 각 탭의 터치 영역은 최소 `44 × 44`이다.
- 바텀시트나 모달이 열린 동안 탭바를 조작할 수 없다.
- 추천 탭은 v1·v2에서 잠금 상태로 정의되어 있다. 눌러도 이동하지는 않고 모달을 띄운다. 

## 9. 알림

- 매일 오전 8시(KST)에 1회 발송한다.
- v1에서는 사용자가 끌 수 없고 v2에서는 유형별 on/off를 제공한다.
- `D-3` 이내 임박 재료, 오늘 만료 재료, 당일 추천 요리 1건을 묶어 알림 1건으로
  발송한다.
- 대상이 0건이면 발송하지 않는다.
- 최대 99개를 보관하며 초과 시 읽음 여부와 관계없이 오래된 알림부터 삭제한다.
- 읽지 않은 개수 배지는 최대 99이며 0이면 숨긴다.
- 만료·임박 알림을 누르면 해당 재고 상세로 이동한다. v1 알림은 이 유형만
  제공한다.
- PWA 푸시 알림을 사용한다. 앱 접속 중에는 우측 상단 알림 아이콘의 숫자를
  증가시킨다. AOS는 기본 푸시 알림, iOS는 잠금 화면과 알림 센터, macOS는 화면
  우측 상단 배너, Windows는 화면 우측 하단 슬라이드 알림으로 표시한다.

## 10. 표기와 접근성

- 날짜는 `YYYY.MM.DD`, 시각은 `오전/오후 h시` 형식으로 표시한다.
- 색상은 무채색만 사용한다. 상태는 채움·테두리·카드 좌측 상태 바로도 구분하고
  원색을 사용하지 않는다.
- 탭 가능한 요소의 터치 영역은 최소 `44 × 44`이다.
- 텍스트가 영역을 넘으면 말줄임표(`…`)로 처리하고 전체 값은 상세 화면에서
  확인할 수 있게 한다.
- 화면 좌우 여백은 `20`, 요소 간 기본 간격은 `12 / 20 / 32`이다.

## 11. 권한

권한은 비트 플래그로 관리하며 `사용자 < 방장 < 운영자` 계층을 갖는다. 상위
역할은 모든 하위 역할의 권한을 포함한다.

| 역할 | 권한 |
| --- | --- |
| 사용자 | 냉장고 참여 및 나가기 |
| 방장 | 사용자 권한 + 참여자 내보내기 + 초대 코드 생성 |
| 운영자 | 방장과 사용자의 권한을 포함한 모든 권한 |

## 12. 뒤로가기와 새로고침

- 인앱 뒤로가기와 브라우저 뒤로가기는 동일하게 이전 화면으로 이동한다.
- 새로고침하면 입력 중이던 값을 초기화한다.
- 필터·정렬 조건 유지의 전체 범위는 별도 확정 전까지 보류한다. 단, 목록에서
  항목을 눌러 이동한 뒤 돌아오는 흐름에서는 제3장의 목록 복원 규칙을 적용한다.
