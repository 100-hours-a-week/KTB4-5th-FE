# 2026-10-04 로컬 일반 탭에서 MSW Mock이 응답하지 않는 문제

## 🐞 에러 내용

`pnpm dev:msw`로 `localhost:3000`을 실행했을 때, 시크릿 탭의 `GET /api/v1/mock/health`는 `MOCK-200-001`(200)을 반환했지만 일반 Chrome 탭에서는 실제 백엔드의 `GLOBAL-500-001`(500)을 반환했다. 같은 서버를 요청해도 브라우저 프로필에 따라 결과가 달랐다.

## 🔍 원인 분석

일반 탭에서 `navigator.serviceWorker.controller`는 `undefined`였다. `getRegistrations()`에는 활성 워커가 없는 등록 하나가 있었고, Chrome 개발자 도구에는 오래된 등록이 `설치 시도`로 표시됐다. 활성 Service Worker가 없어 MSW가 요청을 가로채지 못했고, 요청은 개발 서버의 백엔드 프록시로 넘어갔다.

| 의심한 원인                         | 확인 결과                                                                                                                                       |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| MSW 환경변수나 실행 명령 오류       | 실행 중인 프로세스가 `pnpm dev:msw`였고, 새 브라우저 세션에서는 같은 서버의 Mock 응답이 200이었다.                                              |
| `/mockServiceWorker.js` 제공 오류   | `localhost:3000/mockServiceWorker.js`가 200과 JavaScript Content-Type으로 응답했고 `public/mockServiceWorker.js`와 내용이 같았다.               |
| 개발자 도구의 **네트워크 우회**     | 일반 탭에서 꺼져 있었다.                                                                                                                        |
| 여러 Next 서버의 포트 충돌          | 3001·3002의 성능 측정 서버도 종료해 봤지만 일반 탭의 증상은 계속됐다. 3000에서는 `dev:msw`가 실행 중이었다.                                     |
| 기존 Serwist 워커와 MSW의 등록 충돌 | 별도 브라우저 세션에서 Serwist 등록 후 MSW로 전환됐고 Mock 응답도 200이었다. 일반 탭의 오래된 등록이 왜 멈췄는지는 이 실험으로 설명되지 않았다. |

**확인된 직접 원인**은 활성 워커가 없었던 것이다. 등록이 최초에 `설치 시도` 상태에 멈춘 이유는 확인하지 못했다. 당시 **새로고침 시 업데이트** 옵션이 켜져 있었지만, 이 옵션이 원인이라는 증거는 없다.

## ✅ 해결 방법

Chrome 개발자 도구의 **애플리케이션 → Service workers**에서 `localhost:3000` 등록을 취소하고, 해당 탭을 닫은 뒤 새 탭에서 다시 접속하도록 안내했다. 이후 사용자가 MSW의 정상 동작을 확인했다. 쿠키나 전체 사이트 데이터는 지울 필요가 없었다.

다음 명령으로 복구 결과를 확인한다.

```js
console.log(navigator.serviceWorker.controller?.scriptURL);
fetch("/api/v1/mock/health")
  .then((response) => response.json())
  .then(console.log);
```

정상이면 controller URL이 `/mockServiceWorker.js`로 끝나고 응답의 `code`가 `MOCK-200-001`이다.

## 회고

- Next 서버 재시작만으로는 브라우저 프로필에 남은 Service Worker 등록이 삭제되지 않는다.
- 시크릿 탭과 일반 탭의 결과가 다르면 서버 설정뿐 아니라 각 프로필의 controller와 등록 상태를 확인한다.
- 활성화되지 않은 이유를 확인하기 전에는 **새로고침 시 업데이트**나 Serwist 충돌을 원인으로 단정하지 않는다.
