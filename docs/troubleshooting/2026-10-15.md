# 2026-10-15 로그아웃 성공 후 세션 만료 화면으로 이동한 문제 (PR #242)

## 🐞 에러 내용

MY에서 로그아웃하면 로그인 화면으로 바로 이동해야 하는데, `/login?reason=session-expired`로 이동하면서 로딩 화면이 보였다. 로그아웃 확인 버튼의 진행 표시도 페이지 이동이 끝나기 전에 사라졌다.

2026-10-14에 수집한 Chrome 성능 Trace(`Trace-20261014T211812.json.gz`)에는 다음 순서가 남아 있다. Trace 원본은 로컬 분석 자료이며 저장소에는 포함하지 않았다.

| 순서 | Trace에서 확인한 요청·이동 | 결과 |
| --- | --- | --- |
| 1 | `DELETE /api/v1/auth/sessions` | 200 |
| 2 | `GET /api/v1/refrigerators/current?status=ACTIVE` 2건 | 각각 401 |
| 3 | `GET /api/v1/notifications/settings` 2건 | 각각 401 |
| 4 | `POST /api/v1/auth/token-renewals` | 요청 시작 후 네트워크 종료; 응답 상태는 Trace에 없음 |
| 5 | `/login?reason=session-expired` | 탐색 시작 |

## 🔍 원인 분석

- 로그아웃 API가 성공한 뒤에도 MY 화면의 조회 요청이 나가 401을 받았다. Trace는 요청 순서를 보여 주지만, 쿠키 삭제 시점이나 각 요청을 시작한 컴포넌트까지 확정하지는 않는다.
- `src/shared/api/fetch-client.ts`는 인증 API가 아닌 요청의 401을 받으면 토큰 갱신을 시도하고, 갱신하지 못하면 `SessionExpiredError`를 던진다. `src/_app/providers/query-provider/query-provider.tsx`는 이 오류를 `expireSession()`에 전달한다. 기존 `expireSession()`은 의도적인 로그아웃 중인지 구분하지 않아 세션 만료 URL로 다시 이동할 수 있었다.
- 버튼 문구는 TanStack Query mutation의 `isPending`을 사용했다. mutation 완료와 브라우저의 `window.location.replace()` 완료는 같은 시점이 아니므로, 이동이 끝나기 전에 진행 표시가 사라질 수 있었다.
- [2026-10-03 기록](./2026-10-03.md)의 냉장고 ID 복구 요청 문제와 증상은 비슷하지만, 이번에는 로그아웃 중 남아 있던 여러 조회 요청의 401과 전역 세션 만료 이동이 핵심이다.

## ✅ 해결 방법

- `useLogout()`이 푸시 구독 해제와 로그아웃 요청을 시작하기 전에 의도적 로그아웃 상태를 표시한다. `expireSession()`은 이 상태에서는 세션 만료 이동을 하지 않는다. 로그아웃이 실패하면 표시를 해제해 이후의 실제 세션 만료 처리를 막지 않는다.
- 로그아웃 API의 401은 이미 로그아웃된 상태로 보고 정상 로그아웃 이동을 진행한다. 성공 경로는 `/login`으로 이동한다.
- 로그아웃 확인 버튼은 별도의 `isLeaving` 상태로 `로그아웃 중...`을 유지하고 중복 입력을 막는다. 요청이 실패하면 상태를 해제한다. 수정 내용은 [커밋 `d1db759`](https://github.com/100-hours-a-week/KTB4-5th-FE/commit/d1db759)과 [PR #242](https://github.com/100-hours-a-week/KTB4-5th-FE/pull/242)에 있다.
- 전체 작업 트리에서 `pnpm test` 104개와 `pnpm build`가 통과했다. 수정 후 동일 조건의 브라우저 Trace는 수집하지 않아 이동 시간 개선이나 401 발생 감소를 측정했다고 주장하지 않는다.

## 회고

- 의도적 로그아웃과 예기치 않은 세션 만료는 같은 401을 보더라도 이동 목적이 다르다. 전역 오류 처리에는 사용자의 현재 의도를 반영해야 한다.
- 요청의 완료와 화면 이동의 완료는 다르다. 페이지를 떠나는 동작의 진행 표시는 mutation 상태만으로 제어하지 않는다.
- 네트워크 Trace의 요청·응답 순서와 코드에서 추론한 호출 관계를 구분해 기록한다.
